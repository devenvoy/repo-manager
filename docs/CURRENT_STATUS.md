# Repository manager: current status

Updated 2026-10-28. This report describes the current working tree, not a released or fully verified product. The supplied `release-desk.html` and `storytold-sync.sh` are the behavioral and visual references. Their single-folder, repeated-permission workflow is being replaced by project-scoped folders and native operations.

## Intended workflow

Create or open a project and choose its folder and provider → add a person, organization, group, or repository → fetch and browse the accessible catalogue → select repositories to manage → review destination paths and clone → inspect local state and check for remote changes → update a clean, behind checkout → browse real release history and download assets. Multiple projects and sources should work in one application.

## Verification evidence and boundaries

After the visual code changes, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `cargo build` pass for the root crate. Before those UI changes, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` passed. The local OAuth listener test explicitly skips its live bind when the sandbox returns `PermissionDenied`, and one live GitHub source test is ignored. The CLI integration test checks that sandbox Keychain refusal is reported while continuing the project and backup workflow; it does not prove a successful Keychain write. Provider pagination, release downloads, credential scope, and local Git workflows are covered by offline fixtures and temporary repositories. CLI token login now reads from standard input, keeping tokens out of process arguments. Browser and webview OAuth code paths now report that token exchange is unavailable instead of inventing a token or a successful login.

Provider pagination and download stream tests use offline fixtures; they do not prove live API transport or a successful private asset download. The earlier app process was launched from this checkout in both the normal and elevated terminal contexts; its window did not appear in the available app inventory. The user supplied a screenshot of the prior repository screen, which establishes its poor visual hierarchy but does not show the new build. The normal launch reported macOS Launch Services connection errors. No visual or interaction pass is claimed. A store-wide OAuth lifecycle test previously could not bind a local port in the sandbox.

## Remaining work, in priority order

1. **Verify the actual desktop workflow:** Run the app in an accessible desktop session; test create project, add/refresh source, search/select, single and bulk clone, local and remote status, update, release fetch and download. Check light/dark, resizing, keyboard use and useful error messages.
2. **Make provider and authentication support honest and complete:** Test GitHub and GitLab with public and private repositories, nested groups and multiple accounts; verify the newly wired project credential helper against live private Git operations; verify authenticated private asset access, including GitLab links. Clearly disable or label providers that are not implemented.
3. **Complete operational feedback:** Show per-repository outcomes and actionable errors in the workspace, real transfer progress, cancellation and retry; refresh local status after operations and keep project switching from misattributing results.
4. **Finish the reference-quality interface:** Refine dense repository and release details, search/filter and platform selection, loading/empty/offline states, responsive layout, purposeful animation and reduced motion. Validate against the actual window rather than screenshots of a prototype.
5. **Make update and download state reliable:** Verify content where checksums exist, preserve version history safely, handle incomplete files and duplicate names, and distinguish verified/current from merely present. Test failures, interrupted downloads, stale data and rate limits.
6. **Remove misleading prototype surfaces:** Retire or clearly isolate unused placeholder views and ensure every visible action performs its stated operation. Update old parity and completion documents so they do not claim unverified functionality.

No distribution or publishing work is required for this task.
